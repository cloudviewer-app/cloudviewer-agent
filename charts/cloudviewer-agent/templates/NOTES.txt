Check the rollout:

  kubectl -n {{ .Release.Namespace }} get daemonset {{ include "cloudviewer-agent.fullname" . }}
  kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/instance={{ .Release.Name }}

Each node should show as Connected in the portal within about a minute.
If pods crash-loop, their logs say why (bad or revoked token is the usual
cause):

  kubectl -n {{ .Release.Namespace }} logs -l app.kubernetes.io/instance={{ .Release.Name }} --tail=20

BETA CAVEAT — one token, many nodes: this chart is beta because agent
tokens are currently per-server. A DaemonSet shares one token across all
nodes, so every node reports as the SAME server in the portal — metrics
from different nodes overwrite each other. That is fine for a single-node
cluster (k3s on one box) and wrong for a real multi-node cluster. GA comes
with fleet enrollment: the reserved enrollToken value will let each node
register itself as its own server.
